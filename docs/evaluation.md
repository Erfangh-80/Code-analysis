# ارزیابی تقریبی Bug-fix

ارزیابی پس از تحلیل شروع می‌شود و Job جداگانه دارد. امتیاز hotspot موجود دوباره محاسبه نمی‌شود:

1. snapshot تحلیل‌شده باید ancestor `HEAD` فعلی باشد.
2. فقط commitهای `snapshot..HEAD` در بازه UTC `[since, until)` دیده می‌شوند.
3. فقط subjectهایی که با `fix`, `bug`, `resolve` تطابق دارند، نشانه احتمالی Bug-fix هستند.
4. برای هر فایل دارای score، تعداد commitهای نشانه‌دار آینده از diff path-based شمرده می‌شود.
5. Spearman بین score گذشته و count آینده گزارش می‌شود؛ tieها average rank می‌گیرند.

حداقل سه فایل و تنوع در هر دو بردار لازم است. در غیر این صورت correlation `null` و دلیل ذخیره می‌شود. پیام‌های commit اثبات رفع باگ نیستند، Bug-fix می‌تواند بدون کلیدواژه باشد، و همبستگی علت‌ومعلول یا «درصد صحت مدل» نیست. merge/rename و history ناقص همان محدودیت‌های تحلیل Git را دارند. وزن‌ها در این MVP کالیبره نشده‌اند؛ هیچ ادعای دقت یا benchmark روی مخزن واقعی ثبت نشده است.
